## abuse protection (2026-10-29)
- backend/ratelimit.py (pure python, in-memory, per process): ASGI middleware installed in main.py. Per-IP sliding windows: 120 req/min general; AI endpoints (suggest, intake/next, section-c/generate, deep-search, graph/expand) 10/min and 100/h -> HTTP 429 + Retry-After; uploads 20/min; exports 10/min. Bodies over 30 MB -> 413. Security headers on every response. CORS limited to ALLOWED_ORIGINS (default localhost/127.0.0.1 5173-5177).
- Central AI budget in llm.py `_ask` (covers every chat_text/chat_json/explain path): global LLM_DAILY_CALL_CAP (2000/24h) and 60 calls/application/24h; when exhausted the app silently uses the offline fallback. Prompts truncated to 8000 chars. Exception text is scrubbed (`ratelimit.scrub`) in `last_error` and HTTP error details; unhandled errors return a generic 500. /api/health reports only `llm: azure-openai|offline`.
- Audit: no key/endpoint in frontend src, vite config, index.html, dist; no secret VITE_ vars (only VITE_API_BASE, VITE_PROXY); the browser only calls the backend API. .env, data/store (incl. evidence) git-ignored. Limits are per process and per IP; behind a proxy set TRUST_PROXY=1.
- Tests: backend/tests/test_ratelimit.py.
